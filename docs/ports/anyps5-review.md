# AnyPS5 library review: what BC5's host can take from it

*Written 2026-10-19. Review only; no code was copied in this pass.*

**Subject:** [AnyPS5](https://github.com/boykopovar/AnyPS5), commit `7f596df48dc743ee26fa83ab7f43c859cfdd339b` (2026-10-19, "Merge pull request #6550"). It is not an emulator: a relinker turns a PS5 executable into a native Linux/Windows binary that links against reimplemented system libraries under `core/libs/prx/<library>/`. Those libraries are the part that matters to us.

**Our side:** KytyPlus (GPL-2.0, [Coder787-source/KytyPlus](https://github.com/Coder787-source/KytyPlus); the box runs `f266548`, this review read `ffe6dba` of 2026-10-18 since the older commit is not fetchable shallowly) plus `backend/kytyplus-patches/0001-bc5-lle-agc.patch`. "We have" below means KytyPlus's `src/libs/*.cpp` as patched.

## 1. Licence verdict

| Check | Result |
|---|---|
| Licence file | `LICENSE` is the GNU GPL **version 2 only**; `README.md` "License" section says the same. |
| Compatibility with our GPL-2.0 host | **Compatible.** Same licence on both sides; a ported file keeps its GPL-2.0 header and names the AnyPS5 path and commit, per CLAUDE.md. |
| Sony material in the tree | None found: no `SCE CONFIDENTIAL` or Sony copyright markers (`grep -rI` over the tree), no `.prx`/`.self`/`.pkg`/`.bin` files, no SDK headers. Types are redeclared in `core/libs/SceTypes.hpp`; third-party code is git submodules under `3rdparty/` (LibAtrac9 from `shadps4-emu/ext-LibAtrac9`, a prebuilt `ffmpeg-core` from `KytyPS5/ext-ffmpeg-core`, SDL2, zstd, mbedtls...). The README's disclaimer: no firmware, keys or proprietary libraries are included or required. |
| Caveat: provenance of some behaviours | A handful of `docs/dev/debt/*.md` entries cite an "SDK 12.000 reference" hosted in a third-party GitHub repo (`peterpuppy/bm`) for error codes and parameter layouts (seen in `libSceSaveData.native.md` for `sceSaveDataMount3` and `sceSaveDataGetConvertProgress`). That is Sony documentation reproduced by a third party. **Do not carry those entries' citations into this repo and do not fetch that source.** The code itself is AnyPS5's own; where we want the behaviour, re-derive it from the title's calls (experiment) and cite the experiment. Everything else in the debt notes cites public emulators (shadPS4, KytyPS5, RPCSX, prosper, SharpProspero), public homebrew, or the authors' own measurements on a PS5 (firmware 13.60), which are citable hardware facts under hard rule 4. |

So: **porting is allowed**, file by file, with attribution, excluding the SDK-sourced entries above. The rest of this document assumes that.

Working conventions that make a port non-trivial: AnyPS5 forbids code comments, throws `std::runtime_error` for every unknown input (`AGENTS.md`), uses its own ABI macro `APS5_VABI` and name-based exports from the relinker; KytyPlus uses `KYTY_SYSV_ABI`, `LIB_FUNC` NID tables, `PRINT_NAME()`, `EXIT_NOT_IMPLEMENTED`. A port is a rewrite of the body into our file, not a file copy.

### What AnyPS5 knows about our two titles

- **ASTRO BOT (PPSA21564) / ASTRO's PLAYROOM:** issue #4317 (closed) isolates an engine assertion (`prop->m_pParent == this`) to the values of `sceAudioOut2PortGetState` and `sceAudioOut2GetSpeakerInfo`: the port's real channel count, output = main, and speaker info carrying the two front angles. Our host passes this already (ASTRO runs), so it is a cross-check for `libAudio2.cpp`, not a port. Issue #7210 (open) reports a crash ~35 s in with the audio threads active; #5645 the "too many objects/batches" assertion we saw once in F76 (run 133) — they attribute it to draw threads racing bone uploads while the flip is held.
- **The second title (PPSA03671):** issue #1033 and discussion #5516 (2026-10-13 to 19): the dump ships only `libc.prx` in `sce_module/`, so AnyPS5 needs a stand-in for `libSceNpCppWebApi` (removed earlier as an engine-shipped module, PR #6901 proposes restoring it) and the pad NID `zBsgF0q8DIM`; `libcohtml.Prospero.prx` and `libRenoirCore.PS5.prx` must be converted separately; `scePlayGo` throws on a missing `playgo-chunk.dat`. One report reaches gameplay on RADV at 1–4 fps (2026-10-16); others stop at the intros or the menu transition. Nothing in the thread about ATRAC9, AudioOut2, dialogs, trophies or NpManager. Their ATRAC9 path would reject the title's configuration-7 streams.

## 3. Ranked short list

1. **AudioOut2: classic rumble from the vibration stream when the pad's audio sink is absent.** `core/libs/prx/libSceAudioOut/src/AudioOut2PadMix.cpp` (`AudioOut2RumbleFromPadFrames`: per-channel RMS of the vibration pair, ≥0.01 → `min(1, 2·rms)·255`) and its use in `AudioOut2Context.cpp` (`PAD_PROBE_INTERVAL` 2 s re-probe of the device), commit `7f596df`. Why: F72/F79 — the DualSense's USB link drops and a DualShock 4 has no audio sink; today the host drops the frames. Port into `audio.cpp` behind the existing pad-port path, sending the two bytes through KytyPlus's `dualsense.cpp` output report (F69 confirmed classic rumble is felt through it). Both titles benefit (ASTRO is haptics-heavy). Effort S; verification is a session on the box with the DualShock 4. *Status: ported 2026-10-19 (F214), not yet run on the box.*
2. **NpManager: state-callback delivery and a consistent signed-out model.** `core/libs/prx/libSceNpManager/Export.cpp` lines 11–130 (callback slots, `CheckCallback` delivering `SIGNED_OUT` once, reachability callbacks), commit `7f596df`. Why: the second title's Np stubs (HANDOFF open gaps) answer errors but never deliver the state a title waits for; a title that registers a callback and polls `CheckCallback` sees no transition on our host. Port the model into `libNp.cpp`; keep `0x80550005` vs `0x80550006` as `TODO(verify)` (AnyPS5's code is shadPS4's PS4 value). Effort S; verify with `KYTY` logging of the title's Np calls. *Status: ported 2026-10-19 (F215) into `network.cpp`, where the loaded `NpManager` table points; not yet run on the box.*
3. **NpTrophy2: the three exports KytyPlus lacks.** `core/libs/prx/libSceNpTrophy2/src/GameInfo.cpp` (`sceNpTrophy2ShowTrophyList` → success, no UI), `src/Context.cpp` (`sceNpTrophy2UnregisterUnlockCallback` → success; `sceNpTrophy2GetRewardIcon(int context, int handle, int reward_id, void* buffer, size_t* size)` shape, from PPSA06888's call sites), commit `7f596df`. Why: trivial, and an unresolved NID in the second title would otherwise surface as a jump to 0 (compare the loose-module symptom in #5516). Re-implement (ten lines); do it only after checking our unresolved-NID log for these names. Effort S.
4. **SaveData: search sort keys and blocks accounting.** `core/libs/prx/libSceSaveData.native/Export.cpp` (`sceSaveDataDirNameSearch` keys 0/1/2/3/5, `%`/`_` patterns, `<dir>.blocks` sidecar, free blocks from file sizes rounded to 32 KiB; `sceSaveDataMount3` failure leaves the result untouched), commit `7f596df`. Why: the second title's slot list and delete path are the F205 area and still the least exercised library on our side; a wrong sort or a zero free-block count is the kind of thing that shows as an empty or mis-ordered slot list. Re-implement from the title's calls (the Mount3 entry's SDK citation is off-limits), cite the experiment. Effort M.
5. **AJM ATRAC9: nothing to port for configuration 7, two ideas to read.** `core/libs/prx/libSceAjm.native/src/Ajm.cpp` lines 278–385 (multichannel header `0x30` as per-channel mono decoders) and the gapless-segment rule in `docs/dev/debt/libSceAjm.native.md`, commit `7f596df`. AnyPS5 rejects indices 6–7 outright (`PatchLibAtrac9.cmake`), so F200 stays open; the only leads remain KytyPS5 `b10bd53`'s "vibration layout" name and a decoder written from the bitstream. Not a port.

Not ranked: Ngs2 (off both titles' paths), Ampr (parity after F206), the dialogs (parity after F205), Pad/VideoOut (ours are further along or a different architecture).

## 4. How a port is done here

- One library per commit; the ported function bodies go into the matching KytyPlus file inside patch 0001, with a header line `// Ported from AnyPS5 <path> @ 7f596df (GPL-2.0)`, and HANDOFF gets an F-entry with the run that verified it.
- Citations in docs and comments point at the AnyPS5 file and commit (public, GPL-2.0), or at the measurement the AnyPS5 debt note describes (firmware 13.60 probes), never at the SDK reference some entries cite.
- Anything that AnyPS5 throws on (`std::runtime_error`) becomes our `EXIT_NOT_IMPLEMENTED` or a journaled fallback, matching how the rest of patch 0001 fails.
