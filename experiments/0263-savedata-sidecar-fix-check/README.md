With the fix built into the shared binary: does loading slot 3 write `i38-slot3-*.blocks` next to the directories (not inside), and does deleting slot 3 remove its directories together with their `.blocks` and `.param` files?

Restoring the directories' mtimes from a `cp -a` snapshot taken before (the lake copy, `save-backup-*` of the bench) with `touch -r`, or taking only the files' mtimes in `save_data_dir_mtime`, would give the old dates back; not done here.

It will show up next to the directory, not inside, the first time the maintainer's play saves on this build; the check is `find ~/bc5-work/_SaveData/PPSA03671 -mindepth 2 -name .blocks` staying empty while `ls ~/bc5-work/_SaveData/PPSA03671/*.blocks` fills.
