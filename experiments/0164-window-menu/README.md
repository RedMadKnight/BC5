# 0164 — a menu bar in the emulator window

**Question.** Can the maintainer open a game image or package and close a running session from
the emulator window itself — a menu bar like other emulators have, usable in fullscreen and from
the pad — without the desktop shortcut scripts, and without the host learning to mount anything?

**Setup.** BC-250, Bazzite, KDE Wayland session at 1920×1080; KytyPlus f266548 with patch 0001
as regenerated by this experiment (`hostMenu.cpp` new, `settingsOverlay.cpp`, `window.cpp`,
`emulator.cpp`, `main.cpp`); design in [ADR 0011](../../docs/decisions/0011-host-window-menu.md).
Build: `distrobox enter ubuntu -- cmake --build ~/bc5-work/kytyplus-build --target kyty_emulator -j8`
(binaries of 09:11 and 09:29). Launcher: [`play-any.sh`](play-any.sh) (installed as
`~/bc5-work/play-any.sh`, desktop entry *BC5 emulator*), which runs `kyty_emulator --menu` with
the settings of `bc5-run.env` and hands a chosen `.pkg` to the unchanged `play-pkg.sh`
(`BC5_PKG=<path>`: the mount at `~/bc5-data/mnt/pkg-play`, the second title's exports,
`--fullscreen`) and a `.ffpfsc` to `play-astro.sh` (`BC5_FFPFSC`, `BC5_FFPFSC_MOUNT`,
`BC5_SYSMODULES_PACK_DIR`: three lines added there). Exit codes: 75 restart (as before), 76 open
`$KYTY_BC5_MENU_DIR/choice.txt`, 77 close the session; `~/bc5-work/menu/` holds `choice.txt`,
`recent.txt` and the browser's last folders.

The window was driven over ssh: a virtual keyboard and mouse through `ydotool` (a `ydotoold`
started for the session), the window focused and the pointer read back with a KWin script
([`drive0164.sh`](drive0164.sh): `focus`, `cursor`, `moveto X Y` as a feedback loop, since
`ydotool`'s absolute moves land at 0,0 under KWin and relative ones are accelerated; KWin's
`print()` is a disabled log category, so the scripts report through `callDBus` to a
`dbus-monitor`). Screenshots with `SHOTS=0164 ./shot.sh <name> 0` (full screen, scaled to
1280×720) are private (the second title's start screen) and stay on the box in
`~/bc5-work/shots0164/`; [`route0164.sh`](route0164.sh) is the scripted first half.

**Addendum, the logging switch** (the maintainer's request, ADR 0011 §6; binary of 10:06). The
title started through `play-any.sh <game.pkg>` with the shortcut's capture settings
(`BC5_GC_DUMP_DIR`, `BC5_DIRECT_TIMING=1`, `BC5_DIRECT_FRAME_PROFILE=1`), measured at its start
screen with [`logsize.sh`](logsize.sh) (bytes the journal and the stderr log gained in 10 s):

| State | `direct.log` | stderr log | Screenshot |
| --- | --- | --- | --- |
| Logging on (start) | +7,630,994 B | +86 B (2 lines) | `f1-emulation-menu`: *Emulation* open over the title, *Logging: on* with its check mark |
| *Logging* clicked → off | +0 B | +0 B | `f2-logging-off`: the item reads *Logging: off*, the bar's right hint says *logging off*; `host menu: logging off` in the stderr log |
| clicked again → on | +7,631,074 B | +86 B (2 lines) | `f3-logging-on-again` |

The two stderr lines a window are the title's own `bc5-direct: shared map ... -22` reports from
the backend library (`backend/src/direct.cpp`), which has no switch; they stop too, because the
backend is only called while the game maps, and they are error reports rather than logging. Not
measured: the frame rate with the switch off (experiment 0162 found the journal's cost invisible).

**Build of the union** (10:17). Patch 0001 as committed at `27338e4` (this menu bar and the logging switch,
the AnyPS5 ports 1-4 and experiment 0165's chain code, merged textually and never compiled as a
whole) was applied to a clean `f266548` tree on the box (`git checkout -- . && git clean -fd src`,
`git apply --intent-to-add`; the tree's previous diff kept as `~/bc5-work/0001-before-union.patch`)
and built with the usual command: 211 objects, no errors, no change to the patch needed; the three
CRLF files stayed CRLF. `play-any.sh` with no path drew the empty window from that binary (the
menu bar, the launcher page with *Logging: on (Emulation menu)* and the package in *Recent*, 60 fps;
screenshot `union-empty-window` in `~/bc5-work/shots0165/`); quit with a signal. That binary is
now the one the shortcuts run.

Timings: the window closes and reopens between sessions (exit, unmount, mount, start) in about
2 s for the empty window and 5 s to the title's first frame; the start screen as before (F203).
Not tested here: the pad (no controller input can be injected from ssh; ImGui's gamepad nav is
wired as for the F2 menu: d-pad/left stick, Cross, Circle, Square = the menu bar; the Guide/PS
button toggles the bar), *Emulation > Pause/Resume* and *Restart* (the existing Space and
exit-75 paths behind the items).

**Verdict.** Passed. The emulator has a window of its own: `play-any.sh` (the *BC5 emulator*
shortcut) opens it empty, the menu bar opens a package or an image through the same mount and
settings as the shortcut scripts, closes the session back to the empty window, and reopens from
*Recent*; it works fullscreen and with the keyboard and the mouse. The host still mounts
nothing. *Emulation > Logging* silences the journal, the host's log and every trace live (0 B in
10 s against 7.6 MB) and `BC5_LOGGING=0` starts a session that way. Open: the pad path (untested), a per-title settings file for a third title (the title
scripts are keyed by file kind), and the two seconds of black between sessions (a session change
is a process change, ADR 0011).
