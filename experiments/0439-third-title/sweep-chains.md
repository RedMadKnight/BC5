How submission works (this is the context for every row):
- `Device::submit_impl` (direct.cpp:1427-1461) copies the root and every IB target that `opt.mapped` accepts, and re-points the IB packets at those copies (1530-1568). A target that is unmapped or too deep is NOP-ed (1560-1564). So the GPU follows chains only as far as this copy goes.
  - With `BC5_DIRECT_IB_CHAIN=1`: `ib_chain::collect` with the chain rule (1428-1449). A chain keeps its depth, up to 4096 segments.
  - With the switch off: the old loop (1450-1461), depth below 3 and at most 64 pieces. A 73-segment chain is cut after segment 3.
- `policy::filter` runs on every piece (1513-1517). The options are the root's (`nested_opt = fopt`, 1514).
- Every other backend pass runs on `main_out` (the root) alone.
- `BC5_DIRECT_IB_CHAIN_FLAT=2` (=1 does compute jobs only) replaces `ib` with the flattened top-level chain before every backend pass (1166-1186). Then the backend passes see every chained segment. Calls are still not flattened, and the unit's own passes never see the flat buffer.
- The unit (`submit` → `submit_split` → `submit_now`) works on the guest root. Only the rows marked yes below follow chains.

## "no" rows that matter, simplest to fix first

1. **`acb_ring` → `compute_ring_refusal` without `mapped`** (U:7796, U:7776). Pass `covered_sorted(*g_dev->sorted_mappings(), …)`. `refusal_in` already follows chains (policy.cpp:249-263). This closes the F332-class hazard of an unchecked indirect dispatch reaching a compute ring.
2. **`register_label_writes` (F899)** (U:17684). Call it per piece with `r.nested[k].executed_offsets` (the cw439 shape at U:17694, but from `r.nested`, which already holds each piece's executed offsets, B direct.cpp:1519-1522).
3. **`cs_inherit_at`** (U:8907, U:8918). Walk the pieces from `collect` in order instead of returning -1 at 0x3f.
4. **Root-offset lists in `nested_opt`** (B direct.cpp:1514). Clear `drop_offsets` and `keep_wait_offsets` for pieces (or map them per piece). Today they hit unrelated packets in pieces.
5. **`k1f412_pass` / `dt412_pass` per piece**: make ip439 the default, and re-`collect` after the sync so a newly imported segment is followed in the same submit.
6. **Backend `main_out`-only passes** (DMA sync, `indirect_check` GPU_CHECK/PRODUCT, `state_stack`, `cu_tables`, `host_indirect`). Run them per piece in the piece loop (B direct.cpp:1500-1523), or rely on FLAT=2, which covers top-level chains only.
7. **Unit indirect-arg check / SKIP_PGM / RT-off / loop_bound / aperture fix** (U:17041-17269). Run the loop over every `collect` piece and record drops per piece. This needs per-piece drop lists in the backend (depends on 4).
8. **Wait handling: `submit_split` / `submit_segment` / `acb_ready` / `f10_note` / `ho430` scans.** This is the hardest. Piece waits are invisible to the host and then dropped by the filter's per-span `written` rule. A real fix needs per-piece keep lists, CPU waits or splits at waits inside pieces, and F10/F4 over piece writes. ab439 (`BC5_0439_ACB_DEEP`) covers the `acb_ready` hold only.

General caveat: everything that "follows" chains does so with chain semantics only under `BC5_DIRECT_IB_CHAIN=1`. With it off, the GPU copy itself (B direct.cpp:1450-1461), `full_state`, the soft CP and `refusal_in` stop a 73-segment chain at depth 3-4. Whether `kDefaults` turns it on is unverified.
