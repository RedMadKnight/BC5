# 0256 — What the existing box logs say about the four AnyPS5 ports (F214–F217): the vibration port rides the DualSense's sink, so the rumble fallback never ran; the save and Np traces were never switched on

**Question.** The four AnyPS5 ports have been in every box binary since 2026-10-19 and are still unverified (Q16). Which of the maintainer's verification list can be settled from logs that already exist on the box, without a run: do the second title's logs show the NpManager callbacks (F215), an unresolved import of the three NpTrophy2 exports (F216) or the save-data search (F217), and do ASTRO BOT's show the rumble fallback (F214)?

**Setup.**
- Read-only greps over `ssh bc250` at 00:21–00:23 on 2026-10-24, between exp 0254's smoke runs (its BOX-LOCK was gone and no `kyty_emulator` ran; every script starts with `pgrep "^kyty_emulator" && exit`), under `nice -n 19 ionice -c3`. Scripts: `exp0256-grep.sh` (part 1), `exp0256-grep2.sh` (part 2); their output is `raw/log-check.txt`.
- Logs read: the maintainer's second-title play of 00:04–00:10 (`~/bc5-work/play-pkg-last.log`, 12 MB, 110,813 lines, binary of 2026-10-23 22:06), the same run as captured by the bench (`exp0194/r-W253a/emu.log`), exp 0242's `raw/R1-play-pkg.log` (19:39, 1.7 MB), the four `tcpH2–H5` bench runs of 23:17–23:58 (`exp0194/r-tcpH*/emu.log`, ~320 KB each), and ASTRO BOT's `~/bc5-work/play-last.log` (the 00:18 smoke run S5A, 52 lines).
- Binary check: `strings` on `~/bc5-work/kytyplus-build/src/kyty_emulator` (built 2026-10-24 00:13; `.prev` is 2026-10-19 09:06) for the three port strings, and the port markers in `~/src/KytyPlus/src/libs/*.cpp`.
- No GPU run, no write to the box beyond `~/bc5-work/exp0256/`.

**Result.**
- **The binary has the ports.** All three strings (`KYTY_BC5_PAD_RUMBLE_FALLBACK`, `reward icons are not supported`, `state callback %d: user %d signed out`) are in the running `kyty_emulator`, and the KytyPlus tree carries the markers of all four ports (`raw/log-check.txt`, "binary").
- **F214, rumble fallback: it never engaged, by design.** In every second-title run the vibration port opens as `port 2 type 10 2 ch 48000 Hz (pad)` — routed to the controller's audio device — and every one of its 301 (maintainer's play) / 515 (exp 0242) trace lines says `device playing`, 94 calls/s at rate 1.000, 0 clears, 0 reopens. The fallback only runs when that device is absent or not playing, so with the maintainer's DualSense and its USB sink up the code path idled for the whole session. No pad-speaker port (type 4) was opened by this title. ASTRO BOT's log has no audio trace at all (`run-astro-kytyplus.sh` sets no `KYTY_BC5_AUDIO_TRACE`) and no pad-device line, so nothing can be said about it from that log. Nothing in any log names the fallback, `rumble`, `DualSense` or `controller audio device`.
- **F215, NpManager callbacks: no evidence either way.** Zero lines matching `NpManager`, `sceNp`, `NpCheck`, `NpRegister`, `state callback` or `signed out` in any log. The lines the port adds are `LOGF` under `PRINT_NAME`, which for the NpManager table is off unless the loader's name logging is on; none of the launchers turns it on. The logs are the direct-submission journal plus the fps/audio traces (`play-pkg-log.sh` line 118: the emulator's stdout and stderr go to the log, `--printf-direction File` for the guest's printf).
- **F216, NpTrophy2 exports: weak positive.** The loader logs `Unresolved import stub called` and `recent stubbed import` through `LOGF` when a stubbed import is hit, and `play-pkg-log.sh` keeps that logging on (only `play-pkg-quiet.sh` sets `BC5_LOGGING=0`). The maintainer's 6-minute play and exp 0242's run have zero such lines, and zero lines naming `trophy` or the three NIDs. So no unresolved import was called in those runs; whether the title imports the three exports at all is still not in any log.
- **F217, SaveData search and blocks: no evidence, and the trace cannot have fired.** `KYTY_BC5_SAVE_TRACE=1` is commented out in both `play-pkg-log.sh` (line 86) and `play-pkg-quiet.sh` (line 80); `bc5-run.env` and `bc5-pkg.env` set no `KYTY_BC5_SAVE_TRACE`. The SaveData library's `PRINT_NAME` and its `save trace:` lines are gated by that variable, so zero `savedata`, `DirNameSearch`, `Mount3` or `save trace:` lines in 12 MB is expected, not a finding. On disk, `_SaveData/PPSA03671/` holds only `sce_sdmemory` (2026-10-23 08:27): no slot directory exists, so no `.blocks`/`.param` sidecar has ever been written. `KYTY_BC5_SAVEDATA_DIR=$HOME/bc5-work/_SaveData-pkg-play` is exported by the launcher, yet that directory is empty since 2026-10-12: only the save-data memory file honours the variable (`libSaveData.cpp`, `save_data_memory_dir`), the mounts and the search use `_SaveData/<title>` under the working directory. Not a defect of the port, but it means the slot test must look under `~/bc5-work/_SaveData/PPSA03671/`.
- Side observation: `AudioOut: opened SDL device …` appears in none of the logs although `AudioOut: SDL audio driver pipewire` does; the audio trace still proves the ports opened. Not pursued.

**Verdict.** Partly settled, nothing contradicted. F214's fallback is confirmed idle with the DualSense (its port is on the controller's sink, device playing throughout), so the DualShock 4 session is the only way to exercise it. F216 has a weak positive: no stubbed import was called in the maintainer's play. F215 and F217 cannot be judged from these logs because the traces that would show them were never switched on; the next second-title run meant for Q16 must export `KYTY_BC5_SAVE_TRACE=1` (uncomment line 86 of `play-pkg-log.sh`) and turn on name logging for the Np tables, then save, list and delete a slot, and check `~/bc5-work/_SaveData/PPSA03671/` for the `.blocks` and `.param` sidecars. Q16 updated; no F-entry of the four is changed.
