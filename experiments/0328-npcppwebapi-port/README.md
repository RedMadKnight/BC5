# 0328 — libSceNpCppWebApi for an offline console: AnyPS5's implementation ported, on top of exp 0327

**Question.** Exp 0327's link-time list shows the second title importing 147 symbols of NpCppWebApi — the PS5's C++
web API (`sce::Np::CppWebApi`): the `Common` runtime pieces (`IntrusivePtr`, `Vector`, `String`, `LibContext`,
`initialize`, `terminate`: 98), `SessionManager::V1` request and response classes (33), `TitleCloudStorage::V1` (5),
and 11 without a candidate name. The host answered every one with a return-0 stub: a constructor that leaves the object
uninitialised, an `operator->` that returns null, a destructor that never releases. Tonight's crash site on the shared
build is exactly an intrusive-pointer release (`test r14; dec [r14+8]; mov rax,[r14]; call [rax+0x50]`). The maintainer:
"Tak: niech sesja przygotuje port NpCppWebApi z AnyPS5 (offline), potem prywatny build do testu." Does the title pass
the moment with the library behaving as a console without a PSN sign-in — objects built and released properly, every
request failing with the console's error?

**Sources.** AnyPS5 (boykopovar/AnyPS5, GPL-2.0, commit 27c88a8), `core/libs/prx/libSceNpCppWebApi/Export.cpp`: the
design and the bodies — each exported C++ member is an `extern "C"` function named by its mangled symbol, taking `this`
explicitly; `IntrusivePtr {object, deleter, libContext}` (0x18 bytes) with the reference count at the console's offsets
(0 in objects, 0x30 in vector bodies) and the deleter the object carries; `String {refcount, buffer, size, context}`
(0x20 bytes); `Vector` bodies with a magic, an element kind and host-allocated storage; request entry points return
`SCE_NP_WEBAPI_ERROR_NOT_SIGNED_IN` (0x80552907, the constant shadPS4 and fpPS4 document for the signed-out console),
parameter setters succeed, response accessors are unreachable after a failed request and stop with the symbol's name
(AnyPS5 aborts the same way). Its two tests (`tests/GuestNpCppWebApiString.cpp`, `GuestNpCppWebApiIntrusivePtr.cpp`) gave
the test pattern. The file keeps the origin and the licence in its header, as CLAUDE.md asks for ported code. Exp 0327's
NID map (`raw/S1-stub-list-resolved.txt`, the calculator) ties each mangled symbol to its NID. The 11 unresolved NIDs
are not covered — AnyPS5's export table has no symbol hashing to them either.

**Setup.** `libNpCppWebApi.cpp` (935 lines, generated by `gen0328.pl` in the scratchpad from AnyPS5's bodies and the NID
map, then reviewed): the helpers ported verbatim with `APS5_VABI` → `KYTY_SYSV_ABI` and `NotImplemented` → a RawLog line
plus the tree's `EXIT`; the 136 entry points of the title's list (135 extracted mechanically, one — the
`IntrusivePtr<Vector<String>>` constructor taking a body, a deleter and a context — added by hand from Export.cpp:1241);
`LIB_VERSION("NpCppWebApi", 1, "NpCppWebApi", 1, 1)` and `LIB_DEFINE(InitNpCppWebApi_1)` with one `LIB_FUNC(NID,
symbol)` per entry point, the `extern "C"` functions referenced by their mangled names. `patch0328.py` = exp 0327's seven
files plus `src/libs/libs.cpp` (the declaration in `namespace NpCppWebApi` and `LIB_LOAD(NpCppWebApi::InitNpCppWebApi_1)`
after `InitNet_1`, the pattern of `LibContentDelete`); `src/CMakeLists.txt` globs `libs/*.cpp`, so the integration only
adds the file. `build0328.sh`: seven units compiled with the shared flags (the new one with `libC.cpp`'s command), the
object added to the link line, the shared archive 825ae1d1; then `SyncOnAddressTests` (0327) and `NpCppWebApiTests`
(this experiment: `String` ctor/append/c_str/dtor within 0x20 bytes, `Vector<String>` pushBack and body release,
`IntrusivePtr` default/copy/`operator->`/release with a fake object's reference count and deleter,
`Vector<IntrusivePtr<…>>` holding and releasing a reference, `LibContext`/`initialize`/`terminate`, a parameter
`initialize`) built against the patched units and run. Verified offline: patch anchors 25/25 on the reconstructed box
tree, the new unit's braces balanced; no compiler on the laptop — the first compile is the box's. Exp 0327's link-time
and first-call RawLog lines stay; the new unit adds `[bc5] NpCppWebApi: not reachable offline, stopping: <symbol>` on
stderr before an `EXIT` if a response accessor is ever reached.

**Run.** `build0328.sh` (~2 min, CPU only, under its lock line), `start0328.sh` (0327's start check pointed at this
binary; RT off, 120 s) — the stderr stub list must now have 147 − 136 = 11 NpCppWebApi entries and the twelve absent —
then the maintainer's play to the crash moment on a shortcut of `~/bc5-work/exp0328/kyty_emulator` with a log per start.
Readings: the moment passes → the NpCppWebApi stubs (with or without the twelve) were the cause; the log's
"[bc5] stubbed import called" lines say which of the remaining stubs ran. The same crash → neither set is it; the
`[bc5] NpCppWebApi: not reachable` line, if present, names a response accessor the title reaches offline (then its
request must be made to fail earlier, or the accessor answered); otherwise the release path at eboot+0x3d75a31 is the
next lead with the twelve and the 136 out of the picture.
